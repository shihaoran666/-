# UI 交接：窄屏手柄操作提示

- 基线：Windows Demo 0.2.4，构建编号 `20261116124313-A575D53C8ABF`。
- 分支：`agent/codex/ui-readability`。
- 修改：`雾灯群岛/Assets/Scripts/PrototypeHUD.cs`。
- 目的：首次玩家在窄屏使用手柄时，常驻操作提示仍显示手柄按键。

## 已确认的问题

`PrototypeHUD.OnGUI` 会先依据最后使用的设备选择操作说明，再用文字宽度与可用宽度比较。超宽分支原来无条件改为键鼠文案。因而在手柄输入且文字超宽时，画面会指示 `E / J / M`，实际需要 `A / Y / View`。在 640×360 的窗口、手柄上船/下船两个状态检查这个分支最直接；是否触发取决于本机字体度量，需在构建中复测。

修复后超宽时分别使用短版手柄或键鼠说明。标题界面和暂停菜单未发现同类的“手柄转键鼠”回退逻辑；它们在窄屏的字号与排布仍需真人查看。

## 验证与交接

- 静态检查：`git diff --check`，确认仅改操作说明分支；未运行 Unity、未改发布包。
- 集成者在 640×360 Windows 图形构建中插入实体手柄，先在港口步行，再登船：各按一次手柄方向键或摇杆，让提示切换到手柄模式；两个状态下检查底部始终显示 `A / Y / View`，无 `E / J / M`，全文不截断。
- 同一场景改用键鼠，检查提示切回键鼠按键；在 800×600 和 1920×1080 再看一次标题、暂停、地图和日志布局。
- 若文字仍超宽，进一步缩短手柄短版，不应切换到另一种设备文案。
- 实体手柄往返、新人独立找路仍待用户/QA 验收。本补丁只修正文案选择，不证明手柄操作手感或 640×360 的实际可读性。
