## 工作规则

1. 先完成实体输入试玩，记录路线卡点、按键、截图、构建编号与试玩日志。虚拟输入 PASS 只证明代码路径，不能代替人类体验。
2. 一个集成负责人独占 Unity 工程和构建；其他 AI 只在独立分支或独立目录产出草案、模型或音效。合并时逐项审查 diff、构建并回归。
3. 暂不以 Steam 商店、主机移植和大规模美术扩张为当前关键路径。先验证探索与航行是否让新人愿意继续玩，再决定内容扩张范围。
4. 现有新文档中的结论属于待复核假设；用户本人决定平台、预算与最终发布范围。

## 工具边界

- Codex：跨文件 C# 开发、审查合并、构建和回归；负责唯一可运行主线。
- GitHub Copilot 或另一代码 AI：独立小任务和代码审查草案；不得同时改同一 Unity 工程文件。
- Unity AI Assistant：读取场景/组件上下文，辅助排查 NavMesh、碰撞、布局和原型场景操作；由集成负责人验证结果。Unity 6.0 可选用，无需为此升级引擎。
- 图像生成工具（ImageGen / Adobe Firefly）：概念图、UI 和 Steam 素材草案；正式素材须统一风格、核对使用权并在游戏实机中复拍。
- Blender：正式模型、动画、灯塔/码头可辨认资产和性能可控的导出；它是制作软件，AI 草图不能直接替代可用模型。
- Unity Sound Generator 或其他音频 AI：占位海浪、船舵、任务反馈音；正式入包前确认授权、音量和循环品质。
- 真人试玩：唯一能验证操作手感、路线理解、文字阅读和实体设备兼容性的环节。
