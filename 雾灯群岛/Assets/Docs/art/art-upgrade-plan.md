# 《雾灯群岛》美术升级计划（灰盒阶段 · 可玩性优先）

> 状态：方案文档。当前工程**没有任何 3D 模型/贴图资产**——整个场景由
> `GameBootstrap.cs` 运行时拼装 Primitive 灰盒（Cube/Capsule/Sphere/Plane）+
> 克隆的 `FoglightRuntimeMaterial`（内建 Standard shader，仅 `_Color` 一项）构成，
> `Assets/Art` 下只有一张概念主视觉 `foglight-isles-steam-keyart-v1.png`。
> 本文不写远期预算表，聚焦两件事：
> **灰盒现在具体在哪些地方伤害可玩性**，以及**从概念图反推出的美术圣经**（接线依据）。

---

## 1. 灰盒美术在哪些具体地方伤害了可玩性（逐点，附证据）

下面每条都对应一行可验证的数值或代码位置，不是泛泛"丑"：

### 1.1 可交互物不可读（最严重）

- 现有交互半径只有 **2.25 m**（`PlayerController.FindNearbyInteractable`，
  `Physics.OverlapSphereNonAlloc(transform.position, 2.25f, ...)`），玩家必须**几乎贴上目标**
  才有 `[E]` 提示。浓雾 + 低对比 + 无招牌外形，意味着玩家要"猜测哪里是交互物，
  再走近确认"，探索体验一半被浪费在盲走。
- 交互物与背景的**相对亮度对比不足**：
  - 石头（`_stone` #575E5C）与雾色（#57707D）对比仅 **1.27:1**——浅滩遗迹、石台、
    坍塌灯塔的主体色和雾几乎同亮度，约 50 m 外（雾保留 82%）就开始糊，再远就融进雾里。
  - 木头（`_wood` #382112）在石头上对比 2.27:1，在石碑底 #1A3D47 上只有 1.29:1——
    修船屋、告示牌与石碑底色互相吞没。
  - 唯一例外是**暖光物体**（`_warmLight` 发光材质，#FF8529，对游戏雾色 2.15:1，
    接近雾中可见性的实用下限），所以玩家实际是"找哪里在发光"来读世界——
    这勉强撑住了信标/棱镜，但代价是**所有非发光交互物（日志/罗盘/告示牌/对白 NPC）
    可读性都排不上**。
- **NPC 剪影 = 裸胶囊体**：艾琳 #2E738C（蓝绿）与雾色对比 **1.02:1**——
  也就是在雾中**几乎不可见**，只能靠 `NpcNameplate`（11 m 上限，2.3–11 m 窗口）
  的名字牌把他们"标"出来。玩家对"那是个人"的直觉认知为零。
- **发现物**（日志/罗盘/贝壳/护符）本来就藏起来鼓励探索，可一旦走近，
  色彩各自差异大但形状区分只有"Cube/Cylinder/Sphere 轮廓+一枚小贴角"，
  4 个物件 + 浅水洼/石台的组合方式足够，问题在**交互时没有确认反馈**……

### 1.2 状态变化不可读

- 信标点亮 = 同一 Sphere 的 emission 从 `Color.black` 变成 `Color(1f,.44f,.08f)*3f`
  （`TideBeaconPuzzle.RefreshBeaconVisual`），**只有颜色变化，没有形态变化**——
  隔着雾，玩家区分"这颗亮了/没亮"完全依赖对橙色亮度的记忆，走回头路时尤其痛苦。
- 灯塔点亮 = `_lighthouseBeacon`（暖光 Cylinder）从 `SetActive(false)` → `true`，
  但灯塔本体高塔无光柱、无扫掠，**"点亮"作为全图情绪峰值没有对应的视觉语言**
  （概念图里最重要的就是这个光束）。
  更要命的是数值：`_lighthouseLight.range = 24f`，而晨湾港与潮汐浅滩相距约 94 米
  （`GameBootstrap` 两岛 z=12 / z=-82）——**玩家在浅滩方向永远看不到那盏灯**。
  同日的 `Assets/Docs/playability-diagnosis-2026-11-09.md` 已把这条列为"回报不可见"的
  核心证据，美术侧的修法是阶段 A4 的光柱（可跨雾可见），而不是把 range 调大。
- 交付/对白/拾取全部只走 HUD 文字。玩家在 11 秒前做的关键选择，5 秒后就只剩一行小字记忆。

### 1.3 目标/方向显眼度倒挂

- `GuidanceMarker` 只更新 `Target/Label`（给罗盘和海图用）。当前唯一的 3D 引导是
  **发光色差**；信标顺序放错重置（`_progress = 0`）时，玩家没有任何世界内指示
  "哪几颗被我弄灭了"，只能回头逐颗看。
- 船速/靠岸判断：`DockingPoint.DockingRadius = 4 m`、需 `_speed < 1.2 但船速提示`
  在 HUD 文字里，浓雾里 4 m 半径窗口**只能靠眼睛判断"我在不在 4 米内"**
  几乎不可能；码头在船头视野里只是一条深色 Cube（木头在雾中亮度也低）。

### 1.4 空间语言缺失（迷路的根源）

- 港口与浅滩的岛屿都是一个大 Cube（34×28 / 38×32），边缘是**垂直切角**；
  倾斜 8°/11° 的岸线 + 高 1 m 的实心 Cube，意味着从船上永远看见"一堵 1 m 的墙"，
  无法用天际线轮廓读出"前方的岛是这种形状"。
- 贴岸航行时 `TouchesShore` 的负反馈（船速归零 + HUD 提示）只有文字，
  擦岸的船体处**没有任何视觉压暗/溅水**，玩家不知道自己"撞到哪了"。
- 雾密度常数 `.009`（指数平方衰减）意味着**能见度与玩家所处海域无关**——
  雾本应是"越靠深水越浓"的导航线索，现在是均匀噪声。

### 1.5 UI 与场景的对比是漏水的

- 当前 UI 用白字 + 琥珀高亮 `#FFBD54`（对深蓝黑 #0A1217 达 11.39:1，很好），
  但暂停菜单的底是 `new Color(.04f,.07f,.09f,.94f)`——**94% 不透明**，
  已接近不透明覆盖，游戏画面背景被几乎完全牺牲。
- 而游戏的**真正的 UI 问题在 3D 侧**：罗盘菱形、任务标记是世界中的 Sprite/棱形，
  在灰盒纯色雾背景上，深色轮廓不能由 UI 雾提供对比；当前罗盘字色
  `CompassHUD` #D1E6E6（对游戏雾色 #57707D 为 4.02:1）勉强够，但菱形几何是冷青色
  `#59CCF2`（vs 雾 2.82:1），**低于 3:1 实用阈**，远处目标标记容易丢。

### 1.6 "危险"是否可读（本作没有敌人，危险=地形）

`core-design.md` 明确第一阶段不做战斗，所以不存在"敌人可读性"。真正的危险是三个：
**撞岸**（`TouchesShore` 让船速归零）、**掉海**（`RecoverIfBelowSea` 传回出生点）、
**驶出地图**（海面 200×200，无边界无提示，唯一退出是清档——同日诊断列为软锁风险）。

- 三者现在**全部零视觉预警**：浅滩/礁石与普通石地在材质上完全一样（都是 `_stone`），
  玩家看不出"这里会撞"；海岸线是 1 m 垂直切角的实心 Cube，也没有"浅水/深水"的色差。
- 修法（阶段 A 内）：给危险区一个**可读的地面语言**——浅滩水面用比深水更亮的青绿
  （现有 `_water` #14475C 之上加一层 #2A6B7A 级浅水带）、礁石顶部加暖橙警示色小尖、
  地图边界用一圈雾墙（视觉可读的"不能过去"），比任何 HUD 文字都省事。

**小结（按可玩性伤害排序）**：
1) 可交互物不可读 > 2) 状态变化不可读 > 3) 危险/边界不可读 > 4) 目标显眼度倒挂 > 5) 空间语言缺失 > 6) UI 边缘漏水。
前三条修起来**不需要任何新模型**——颜色/发光/信标形态调整即可，
是"灰盒也能玩顺"的最低门槛。

## 2. 三阶段路线（验收标准 + 1–2 兼职工时）

原则：**每阶段只做"把当前可玩性伤害最小化"的事**，不追求"变成成品游戏"。

### 阶段 A —— 可读性补丁（纯代码 + 材质参数，0 新资产）

**工时**：1 人 × 3–5 人天（兼职约 1–2 周，可 2 人并行压到 3 天）｜**目标**：不改美术风格，只解决"看不见/分不清"。

| 项 | 动作 | 验收标准 |
| --- | --- | --- |
| A1 交互物发光规格 | 为 `Interactable` 物体统一加轮廓级发射遮罩（未点亮前用冷青 #59CCF2 低强度 emission ~0.4，拾取/点亮类用暖橙）；非交互物禁止暖橙 | 玩家 6–8 m 外凭轮廓+颜色即可猜出"这个能交互"，无 HUD 也能读到 |
| A2 NPC 剪影 | 两个 NPC 胶囊替换为 2–3 个 Primitive 拼的小塑形（帽/衣/油灯，共 ≤5 个 Primitive），颜色改至对雾 ≥3:1 | 玩家 11 m 外（即名板出现距离）能先看到"人形"，名板出现时认知零延迟 |
| A3 状态变化配套 | 信标点亮时加形态变化（顶部升起小 Primitive 柱）；放错重置时全灭 1.5 s + 发光色单帧闪白 | 走回头的玩家不看 HUD 也能数清亮了几颗 |
| A4 灯塔光束语言 | 灯塔点亮时加一支**旋转的暖橙光柱**（细长 Cylinder + emission，或 additive 面片），扫掠周期 4–6 s | 站在浅滩远端也能看到光柱掠过雾层，成为地理定位点 |
| A5 靠岸窗口可读 | 码头边缘加 2–3 个暖橙细条（低强度 emission 打标可停靠侧）；靠岸成功瞬间让船身短暂闪光 | 玩家在 8 m 内即可定位"往哪靠"，不再贴 4 m 盲窗 |
| A6 雾分层 | 手动在两岛之间加 2–3 片低多边形雾板（加透明材质、无碰撞），近浓远淡；深水区雾密度 +20%（可由代码侧轻微动态调 `fogDensity`） | 大雾中视觉读出"距离感"：同色雾不再均匀平铺 |
| A7 港口多样拼装 | 用现有 Primitive 拼出 3–4 种船/屋/植物变体（每个 ≤6 primitive），以便玩家用**轮廓**区分区段 | 转头瞟一眼能分出"办公室/船屋/灯塔"三块 |
| A8 危险可读 | 浅水带用更亮青绿分层；礁石顶加暖橙小尖；海图边界加一圈雾墙 | 玩家在撞岸/驶出地图前**看得见**"这里不能过"，不再靠 HUD 文字兜底 |

**阶段验收**：`-verify-keyboard-journey` 全程不读 HUD 的情况下，玩家可仅凭视觉：
找到告示牌→选船→驶向浅滩→数信标→拾棱镜→返港。这是波次一的结果承诺。

### 阶段 B —— 风格化替换（最少资产量）

**工时**：2 人兼职 × 3–4 周（合计 20–30 人天）｜**目标**：在保持色板/雾/光束语言下，
**替换**最伤害第一印象的那一小撮灰盒。

| 优先级 | 资产 | 动作 | 验收标准 |
| --- | --- | --- | --- |
| B1 | 人物 ×2（艾琳/乔恩） | 低多边形风格化模型（或 Kenney Mini Characters 平台风格化修改）+ 衣服色板 | 对雾 ≥3:1，剪影可读，不追求细节 |
| B2 | 船（晨鹱号） | 一个完整模型（hull+桅+帆+桅灯） | 登船后内部无 Primitive 重叠感；航行时帆/水线有正确接触 |
| B3 | 灯塔 | 一座完整塔模型（塔身+灯室+栏杆） | 塔身与灯室色分区明确；点亮后光柱可装进灯室位置 |
| B4 | 码头/房屋 ×3–4 | 木质模块化或 Kenney Pirate Kit 部件拼装；木纹色板用 CC0 纹理 | 近 2 m 看仍是"有意为之的风格化"，不是"没做贴图" |
| B5 | 地形轮廓 | 两岛的地形从 Cube 改为低多边形宽体（或 Unity 6 terrain 简模），岸线出现可读轮廓 | 天际线可读出"岛"的形状 |
| B6 | 水 | 程序化水面替换为一个平铺法线贴图/顶点波纹（URP 水体或 CC0 水面材质） | 船行过水面有可见扰动，擦岸有反馈 |

**阶段验收**：商店四个截图清单（商店页初稿已有）能各自截到"一眼会认为这是成品"的画面；
概念图 × 实机截图并排，风格承诺成立。**该阶段完成后才有资格谈"要不要 Synty"**。

### 阶段 C —— 打磨（可选，上架前才做）

**工时**：1 人兼职 × 3–4 周（10–15 人天）｜**目标**：把风格语言"说完整"，不新增大件。

- 概念美术反推出的雾分层/光束语言落进 **post-processing**（Bloom + 暖橙四分色）
  ——当前工程连 Default Volume profile 都是空的。
- 信标/灯塔/发现物的**粒子**（水汽/光尘/拾取碎光）。
- 发现物特写与对白时的**镜头语言**（准一秒的对焦收放）。
- UI 2D 皮肤与 3D 标记统一色板卡片（见 §4 最后一节）。

**阶段验收**：实机画面与概念图并排可以"标出三处一致 + 一处差异"，
且差异是被动接受的可权衡项。

## 4. 美术圣经（从概念主视觉反推，波次二接线的依据）

以下全部从 `foglight-isles-steam-keyart-v1.png` 实测（1672×941，直方图/取色器）：
色相分布、分区亮度、暖光占比 6.7%（面积）、最亮 0.5% 像素质心位于画面 72%/45% 等。

### 4.1 色板：蓝黑/灰绿环境 + 暖橙/猩红高亮

实测概念图色相分布（面积排名）：

| 角色 | 主色 | 用途规则 |
| --- | --- | --- |
| 雾/远景主体 | #525E64（30%）、#344953（24%）、#263B44（14%）、#1A2D30（16%） | 所有环境材质、雾色、远景岛轮廓；最深的 #1A2D30 只允许出现在最远处，中近景不得压到这个深度 |
| 中景水面/石 | #627886、#6F8694 | 石头/码头/船身上的**受光面** |
| 暖橙（灯塔/灯） | #D89862、#AC8569、#96735C | **只有人造光源和它直接照亮的表面**允许，面积 ≤7% |
| 猩红/深褐（余烬） | #5B2715、#5B2F17 段 | 暖橙的"骨"，用于灯芯/火心/背光暗部——**不是独立色，是暖橙的暗端** |
| UI 白/纸 | #98948F | UI 白不用纯白，用带暖灰的纸白 |

**硬规则**：
1. 冷暖比例 ≈ **93 : 7**——任何画面里，暖色像素面积占比测试（可用截图脚本自动化）超过 ~10%
   就是"过节了"，低于 ~4% 就是"灯塔电池没电了"。
2. 冷端四种雾色（#525E64/#344953/#263B44/#1A2D30）构成**雾的色阶**，越远越向 #1A2D30 收，
   这是 §4.2 分层的色板基础。
3. UI 琥珀 #FFBD54（现有 UI 已在用）与概念图暖端同族，**UI 是世界光源色温的延伸**，
   不要把 UI 做成纯色白。

### 4.2 雾的分层（与 audio-plan 的雾声学联动）

概念图实测：亮度自下而上、自右至左，呈**三层结构**——
下层(meanL 58)最暗（近处水面+船体暗部）、中层一段最亮（雾面反光），
上层先亮后回落，**暖光像素在雾顶 0–20% 带占 11.9%**——光束打在雾顶最浓，
这是"暖光扫描雾"的视觉签名。

规则（阶段 A6、阶段 C 的分层依据）：
- **近景雾要薄**（看得见船体/人物剪影），**中景最浓**（与概念图中层最亮一致），
  远景靠色阶（#525E64→#1A2D30）读深浅。
- **光束只在雾层里显形**：光柱经过的雾层不透明度显著提升（分层雾板 + additive 光柱的组合）。
  没有雾层的背景处（如高处/天空），光柱反而应淡出，防止"激光笔"感。
- 当前实现是**均匀常密度雾**（`fogDensity .009`），与概念图"三层+暖光扫描雾"完全不符，
  是阶段 A6 的核心任务。

### 4.3 灯塔光束语言

概念图最亮 0.5% 像素的质心落在画面 (72%, 45%)——**光束是唯一超亮的元素，
也是唯一"有方向"的元素**：
- 光束颜色实测中心 #EFC68E（对概念图雾底色 #263B44 为 7.33:1）→ 边缘 #D89862 → 触雾即散（衰减至透明）。
- **扫描节奏**：光打到雾上，雾是"被动显形"，光柱本体保持针一样细——
  针细光柱 + 雾面投影是这条艺术语言的关键对（不是粗卤素光柱）。
- 周期 4–6 s（与 audio-plan 的灯塔机械循环音频建议同周期）。
- **灯塔灭 = 光束不存在的负面空间**。灰盒阶段灯光 `SetActive(false)` 是对的，
  但升到阶段 A4 后注意：灯塔暗时，塔身在雾里应是**深色剪影**（#1A2D30 级），不是"消失"。

### 4.4 NPC 剪影可读性

概念图里没有 NPC，画面靠"冷雾 + 一点暖光"交代有人活动；把这条转成灰盒规则：
- NPC 必须自带一个**暖光锚点**（油灯/灯笼/烟斗余烬，同 `_warmLight` 族），
  剪影靠"冷雾中一团暖色 + 人形填补"被读到。人形可识别需要轮廓对雾 ≥3:1；
  艾琳 #2E738C 凭自身色只有 **1.02:1 —— 不达标，必须挂灯**，
  乔恩 #E09633 是 2.13:1，勉强但同样建议补灯。
- 剪影差异：艾琳（管理层）直背+持卷轴/名板；乔恩（匠人）微弓+持锤/工具带。
  用 ≤5 个 Primitive 拼出这两种站姿差异，比换模型更优先。

### 4.5 UI 与场景的对比规则

- 文字/数字/目标标记：**冷雾背景上只允许两种 UI 色**——
  纸白 #E8F5F3（对游戏雾色 #57707D 为 4.67:1，正文可用）与琥珀 #FFBD54
  （对雾 3.15:1，**只用于 ≥18 px 粗体的标题/选中态**，不能作正文）。
- **#59CCF2 冷青色禁止作为目标标记的主色**（vs 雾 2.82:1，不达标）——
  但允许它作为交互 affordance 的**次级色**（轮廓光），因为附近有 HUD 文字替玩家确认。
- 深色覆盖层（暂停/对白/地图）不透明度 ≤0.85，保证场景剪影仍占一席之地
  （当前暂停 0.94 接近全遮，建议下调）。
- HUD 元素一律带 **≥0.55 alpha 的黑底板**（现在部分提示有，部分没有），文字对比以
  "底板黑 ≠ 场景雾"（#0A1217 级，vs 雾底可达 11:1+）为达标口径。
