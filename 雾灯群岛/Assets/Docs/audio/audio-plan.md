# 《雾灯群岛》音频计划（灰盒阶段）

> 状态：方案文档，未接入任何音频资产。当前引擎内唯一的声音是 `AmbientSoundscape.cs`
> 运行时合成的 18 秒单声道海风 + 潮声循环（44.1 kHz，正弦振荡 + Perlin 噪声泡沫），
> 没有音乐、没有任何采样音效。本文档面向**爸爸验证整体可玩性**的当前阶段，
> 不是上架素材预算表；上架相关的授权整理请在确认要发 Demo 后再补一份逐条核实的清单。

## 1. 现状诊断：只有程序化海风，对探索体验的伤害是什么

玩家现在在灰盒场景里听到的是：一条音量 0.72 的 18 秒循环，
内含 0.075 Hz 缓慢起伏的“风”、0.31 Hz 的“潮”、Perlin 噪声泡沫，整体峰值被钳在 ±0.18。
问题不在它难听，而在它**什么信息都不给玩家**：

| 短板 | 具体伤害 |
| --- | --- |
| **零事件反馈** | 接任务、点亮信标、拾取棱镜、交付、灯塔点亮——当前 100% 靠 HUD 文字（`PrototypeHUD.SetMessage`）传达。探索游戏的“发现感”一半来自声音确认；现在玩家做完任何事，耳朵得到的都是同一条海风，情绪曲线是平的。 |
| **零空间感** | 整条音轨 `spatialBlend = 0`、单声道，港口灯火、浅滩水洼、船身侧的浪没有位置差异。玩家在浓雾里唯一的定位向量本来就该是“声音从哪边来”，现在是零。 |
| **零节奏** | 30–45 分钟的垂直切片只有一条恒定听觉背景。标题界面、暂停、读档、正常航行、靠岸后徒步，听起来一模一样；暂停时只靠 `AudioListener.pause` 一刀切，没有“菜单里世界安静了”的层次。 |
| **零情绪锚点** | 核心体验承诺是“雾、灯、余烬暮色”。当前声音是中性的风声，既不暖也不冷，帮不上灯塔点亮时的那个“该起鸡皮疙瘩了”的时刻。 |
| **循环伤痕** | 18 秒循环、首尾用同一个 `fade` 包络压到零，会形成可闻的“呼吸式”节拍；“什么都没有”本身成了可预测的规律。 |

与同日《可玩性诊断》对齐（`Assets/Docs/playability-diagnosis-2026-11-09.md`）：
诊断给「视听」打 2/10、并指出灯塔 `range = 24f` 而两岛相距 94 米——**修灯塔的光在海上永远看不到**。
这意味着音频在这里不是锦上添花，而是**唯一能跨 94 米把"灯塔亮了"传给玩家的通道**：
一声低频轰鸣 + 一段暖色乐句，是当前架构下最便宜、也最有效的回报反馈。

**灰盒阶段结论**：可玩性验证（能不能找到信标、能不能读懂谜题、会不会迷航）不依赖音乐，
但**强烈依赖反馈音**。玩家在雾里靠文字提示找第三座信标时，一声“点亮”比一行 HUD 文字有效得多。

## 2. 最小成本立刻改善听感的三件事（不引入任何音频文件）

按投入产出排序，都可以在现有 `AmbientSoundscape.cs`（或其旁挂一个新组件，不改这三个文件）里完成：

1. **给关键事件加程序化“确认音”**——优先级最高。
   - 触点已有现成钩子：`TideBeaconPuzzle.Activate` 成功/失败、`_quest.CollectPrism`、
     `Interactable.Interact`（告示牌/石碑/发现物/对白开始）、灯塔点亮（`RefreshWorldForQuest` 中
     `lighthouseRestored == true` 分支）、信标顺序放错重置。
   - 做法示例：点亮信标 = 短促上滑正弦（例如 620→880 Hz，120 ms，指数衰减）；
     拾取棱镜 = 两音上行五度琶音；灯塔点亮 = 低频“轰”+ 高频泛音长尾；
     顺序放错 = 下滑噪声短音。每个 0.1–0.5 秒，运行时生成、缓存成短 `AudioClip`，成本几乎为零。
   - 这是“探索游戏可玩性”最直接的音频补强：玩家做对了会**听到**自己做对了。

2. **把环境声拆成两层，并给船加上随航速变化的水声**
   - 现在只有一条背景。拆成：**底层**（风+潮，缓慢、恒定，继续程序生成但去掉首尾 fade 改成
     交叠拼接或全周期闭合波形，消掉 18 秒呼吸痕）+ **船层**（随 `BoatController.Speed` 映射的
     轻微水声起伏/Hull 摩擦，幅度和滤波随航速变化，登船后淡入）。
   - 附带一个便宜的“雾的厚度”映射：`RenderSettings.fogDensity` 现在是常数 .009，
     随它把风声高频轻微压暗，雾里声音真的“变闷”，这是氛围游戏最便宜的真实感。

3. **把暂停/标题的静音改成淡出，并加一层“界面感”**
   - `AudioListener.pause = true` 是瞬间切，改为 0.5–1 秒音量淡出（每帧把 `volume` 向 0/1 缓动，
     而不是动 `AudioListener.pause`）；标题界面单独一层更慢、更空的“远方灯塔低鸣”程序音，
     与游戏内区分开。暂停菜单本身已有音量滑杆接管 `AudioListener.volume`，不动它。

> 顺手补一条：**对白节奏**。`DialoguePanel` 的推进目前只跟玩家按键，没有声音节拍；
> 加一个极轻的每行推进“纸页”点击（程序化 30–60 ms 短噪声即可），长句阅读感会明显好一截。

## 3. 音乐需求表（场景 × 情绪 × 时长 × 循环）

灰盒验证阶段**不需要任何音乐**；下表是接采样音频（波次二）时的最低配预算，
每一行都做了“能不能被程序音或环境声替代”的标注，避免提前买素材。

| 场景 | 情绪 | 目标时长 | 循环 | 最低配方案 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 标题 | 静谧·遥远·余烬 | 60–90 s | 是，无缝 | 可先用程序生成的“远方灯塔低鸣”垫底 | 标题是第一印象，正式版必须有真乐 |
| 晨湾港白日 | 温和·人间气 | 90–120 s | 是 | 可用环境声 + 偶发港口细节音替代 | 音乐在港口应是“若有若无” |
| 航行 | 开阔·微微紧张 | 90–150 s | 是 | 可由环境声 + 船层替代，音乐可推后 | 音层设计见 sfx-integration |
| 潮汐浅滩 | 谜题·潮音共鸣 | 60–90 s | 是 | 可用“三座信标的持续低鸣”程序音替代 | 信标全亮后可整体抬一档 |
| 谜题推进 | 澄清·点亮 | 8–15 s | 否（过渡乐句） | **必须**，程序音可先顶 | 与信标确认音合并即可起步 |
| 任务完成 | 温暖·回报 | 10–20 s | 否（定格句） | **必须**，交付/升级共用 | 三条任务各一次，频率低 |
| 灯塔点亮 | 高潮·暖光扫过雾海 | 25–40 s | 否 | **必须**，试玩版情绪峰值 | 只此一次，可上诉细节音配器一次 |
| 试玩结束 | 归航·余韵 | 30–60 s | 否（或接循环） | 可用“灯塔点亮”变奏 | 完成第三任务后的过场/自由探索 |
| 暂停 | 抽离·静观 | 20–30 s | 是 | 无音乐，环境声淡出即可 | 保持极简 |

**真正的硬需求只有三条**（谜题推进 / 任务完成 / 灯塔点亮），其余都能被环境层撑住——
这与“垂直切片先验证可玩性”的阶段相称。

## 5. 禁用来源（红线，任何情况下不进工程）

- **盗版音乐包、破解版音效库**（e.g. 一切“XX 大全合集”命名、来源为网盘/种子站的音乐包）。
- **来源不明的短视频热歌**（抖音等平台的 BGM 无法核实授权，哪怕“听起来像氛围乐”）。
- **影视/游戏原声 OST**（无需解释，任何形式的 rip 都不行）。
- **未标注授权的网盘资源**（“作者忘了写 license”不等于可用；无明确条款 = 不用）。
- **CC BY-NC / “非商用”条款的任何素材**：只要将来可能上架（Steam 即商业发行），非商用条款就不可用，直接排除。
- **授权无法在源站复核的搬运/转载**（B 站转载、公众号文章内的“打包下载”等）。

## 6. 落地顺序小结

1. **本阶段（灰盒可玩性）**：只做第 2 节的三件事（事件确认音 / 环境分层 / 淡出），
   不引入任何音频文件；验收标准为“做完信标谜题、拾取、交付、灯塔点亮四个动作，
   每个动作都有可辨识的听觉确认，且暂停淡出不突兀”。
2. **波次二**：按第 4 节采样表逐条核实授权后，按 sfx-integration.md 的 AudioMixer 分组接入；
   先接 P0 音效（脚步、撞岸、UI），音乐最后。
3. **上架前**：补一份正式的《素材授权台账》（每条：来源 URL、授权类型、下载日期、署名要求、
   工程内路径），Steam 提交时随批发材料备查。
